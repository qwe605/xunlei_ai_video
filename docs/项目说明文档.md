## 1. 项目概述

### 1.1 项目定位

“迅雷 AI 片库”面向拥有大量云盘或本地视频的中国大陆用户，解决“文件名记不住、长视频
不知道内容、只能拖动进度条寻找片段”的问题。系统把视频音轨转换为带时间轴的字幕，并在
字幕基础上生成摘要、标签和章节，使用户能够用自然语言找到视频及对应时间片段。

当前仓库是一套可运行、可交互、可测试的产品 Demo。它包含两类能力：

| 类型 | 当前实现 |
|---|---|
| 稳定评审体验 | 3 个中文、1 个英文真实有声视频及预生成 AI 索引；无需等待模型即可搜索、播放、查看字幕和章节 |
| 本地真实分析 | 上传 MP4/WebM，经 FastAPI、音轨校验、ASR、MiniMax-M3、结构校验后生成结果，并写入服务端片库 |

### 1.2 核心目标

1. 自动从无字幕视频的音轨生成 WebVTT 字幕。
2. 为视频生成简体中文摘要、关键词和可跳转章节。
3. 支持文件名搜索和基于字幕、摘要、章节的自然语言检索。
4. 回答当前视频的问题，并给出可核验、可跳转的时间证据。
5. 对没有视频证据的问题明确拒答，不使用模型常识编造答案。
6. 展示本地导入、任务排队、失败、重试和完成状态。

### 1.3 当前能力边界

- **已实现**：默认登录页、本地视频导入、浏览器元数据读取、真实媒体播放、字幕同步、
  预生成内容检索、服务端自然语言搜索接口、本地 AI 分析 API、任务持久化、片库持久化数据模型、
  媒体/字幕读取接口、分析结果落库、前端启动读取服务端片库、封面资产持久化、观看进度保存、
  AI 结果反馈入库、磁链格式校验与本机协议调用。
- **Demo 实现**：注册登录只保存在浏览器本地，不是迅雷账号；未登录时前端会拦截片库、
  播放器、导入和搜索页面；内置问答来自经校验的样例数据；内置视频仍由前端静态数据
  保障评审稳定，本地导入视频已通过服务端持久化。
- **未实现**：真实迅雷云盘文件列表、迅雷账号 OAuth、云端磁链转存、在线多用户权限隔离、
  生产级向量数据库和分布式任务队列。
- **明确禁止的误解**：视频内嵌字幕只可作为离线 ASR 评测标准答案，生产字幕生成不使用 OCR
  或内嵌字幕。

```mermaid
    R --> V["真实视频 / WebVTT"]
```

### 3.1 分层约束

后端依赖方向为 `Controller -> Service -> Repository / Integration`：

- Controller 只定义地址、参数、HTTP 状态码和响应。
- Service 编排上传、模型调用、状态流转和临时文件清理。
- Repository 是 ORM 数据访问入口；Controller 和 Service 中不散落原生 SQL。
- Integration 隔离 ASR、MiniMax 和操作系统协议等外部能力。
- Schema 同时约束 HTTP 数据与模型结果。

前端依赖方向为 `main -> App -> views/features -> components/api/lib/data`：

- `App.tsx` 持有跨页面状态和任务轮询。
- `views/` 负责完整页面。
- `features/` 负责导入、账号、队列等跨页面业务。
- `api/` 只负责请求后端和校验响应。
- `data/` 提供领域结构与预生成样例数据。

## 11. 关键状态流转

```mermaid
stateDiagram-v2
    [*] --> queued: 上传完成并创建任务
    queued --> processing: 后台线程开始
    processing --> completed: ASR 与内容整理通过校验
    processing --> failed: 媒体、ASR、MiniMax 或结构校验失败
    queued --> failed: 服务重启，旧任务中断
    failed --> queued: 前端用户重试并创建新任务
    completed --> [*]
```

前端将后端 `failed` 映射为可重试的阻塞状态展示；后端重启时不会让旧任务永久停留在
“处理中”，`AnalysisJobRepository.fail_interrupted()` 会把遗留 queued/processing 任务标记失败。

## 15. 当前不足与改进优先级

### P0：提交公网链接前必须处理

1. **前端已有 Demo 门禁，但还没有服务端鉴权与数据隔离。** `App.tsx` 会在没有本地会话时
   拦截片库、搜索、导入和播放器页面，`AccountDialog.tsx` 只使用 localStorage；后端分析接口
   仍无登录校验和用户字段。公网部署后仍必须接入正式身份服务，在数据库增加 user/tenant
   归属，并为上传和查询增加授权、限流和配额。
2. **任务执行器只适合单机 Demo。** `AnalysisService` 使用 `ThreadPoolExecutor(max_workers=1)`；
   多用户会长时间串行等待，进程退出后任务不能恢复。应改为 Redis + Celery/RQ/Dramatiq 等
   独立任务队列，并提供取消、超时、重试次数、预计等待时间和并发控制。
3. **远程部署后磁链唤起逻辑不成立。** `os.startfile(magnet)` 只会打开后端所在 Windows 主机。
   公网 Linux 服务不能唤起用户电脑。应使用受用户手势触发的前端协议链接、桌面助手，或接入
   迅雷内部云盘离线任务 API；当前服务端系统调用只能保留为本地 Demo 能力。
4. **部署底座已有 Compose，但还不是完整生产方案。** 当前已有 Dockerfile、Compose、Nginx
   反代、数据卷、模型缓存卷和环境变量密钥注入；仍缺后端进程守护策略、HTTPS、数据库备份、
   监控告警、灰度发布和对象存储迁移。

### P1：影响核心产品说服力

1. **自然语言搜索已服务化，但仍缺真实向量索引。** `SearchPage.tsx` 会优先调用
   `POST /api/v1/search`，后端通过 `SearchService` 融合标题、文件名、标签、摘要、章节和字幕
   分片得分，并返回 citation；但当前还没有中文 embedding、pgvector、倒排索引持久化和
   rerank。片库扩大后语义泛化仍会受限，建议下一轮复用 FlagEmbedding + pgvector。
2. **“问视频”已接入后端 RAG 雏形，但还缺问答持久化和向量召回。** `PlayerPage.tsx` 优先调用
   `POST /api/v1/videos/{video_id}/questions`，后端只在当前视频章节和字幕分片中检索证据，
   并要求 MiniMax 返回候选 citation；但问答历史、embedding 检索和质量指标尚未落库。
3. **片库持久化已具备单机底座，但还缺生产级生命周期。** 本地导入视频、source/poster 资产、
   AI 字幕、章节、标签、字幕分片和观看进度已落库，也能删除对应记录和文件；下一步需要补
   分页、配额、真实用户隔离、定期巡检孤儿文件和对象存储迁移。
4. **MiniMax 失败会使整个任务失败。** ASR 已完成时仍无法向用户交付字幕。建议保存阶段性产物，
   先提供字幕，再异步重试摘要和章节，使部分成功可见。
5. **精准模式 CPU 推理等待较长。** large-v3 已改为部署前安装并校验，运行期不再下载；队列会按
   已识别的音频时间持续显示进度。`6月13日 (2).mp4` 的实测为 541.955 秒视频转写 997.06 秒，
   CPU 实时因子约 1.84。当前仍没有队列位置、取消和后台通知；服务器应安装 CUDA 12 cuBLAS
   与 cuDNN 9、使用 GPU 量化服务，并在相同 Ground Truth 上记录 CER 与实时因子。

### P2：工程质量与体验优化

1. **缺少数据库迁移。** `Base.metadata.create_all()` 只能建新表，不能安全升级已存在的表。应引入
   Alembic，并把 SQLite 明确限定在本地；多实例使用 PostgreSQL。
2. **前端大文件需要拆分。** `global.css` 约 2456 行，`demoLibrary.ts` 约 504 行，`PlayerPage.tsx`
   约 403 行，`ImportVideoDialog.tsx` 约 372 行。建议按播放器字幕/问答、导入本地/磁链、页面主题
   拆分，降低修改冲突和回归风险。
3. **移动端触控目标偏小。** 实测部分筛选和推荐按钮高度约 31 px，低于常用的 44 px 触控建议。
   应在移动断点提高最小高度和按钮间距，同时保持当前无水平溢出表现。
4. **缺少任务清理策略。** `analysis_jobs` 没有分页、保留期和过期删除；长期运行会累积 JSON 结果。
   应增加按用户分页查询、归档/清理任务和数据库容量监控。
5. **可观测性不足。** 通用异常被转换为友好错误是正确的，但后端没有结构化日志、请求 ID、任务
   耗时、ASR/LLM 指标和告警。生产环境应记录不含原始视频/字幕/密钥的脱敏指标。
6. **中文素材覆盖仍较单一。** 4 个内置视频已调整为 3 个中文、1 个英文，但三条中文均来自同一
   原视频的不同区间。后续应增加不同题材、说话人、口音和噪声场景，并持续记录 CER。
7. **部分 Schema 产生 Pydantic alias 警告。** 自动化测试通过，但 `MagnetOpenRequest`、
   `ProgressUpdate`、`SearchRequest` 和 `FeedbackCreate` 等模型与全局 alias 生成配置组合会输出 alias 元数据
   无效告警。应统一按 Pydantic 推荐写法调整，并增加无警告测试。
8. **前端尚未拆包。** 当前主 JS 为 468.29 kB（gzip 142.17 kB）；Demo 可接受，但接入真实
   检索、图表或更多播放器能力后应按页面动态导入，并单独延迟加载 Plyr。

## 16. 推荐的下一阶段实施顺序

1. 先完成公网部署安全底座：真实鉴权、上传限流、配额、任务取消和密钥管理。
2. 把视频、字幕、章节和进度从 React 内存迁移到 ORM + 对象存储。

5. 在相同 citation schema 上接入任意问题 RAG，保留无证据拒答。
6. 增加中文多场景评测集，分别衡量 CER、章节覆盖、检索 Recall@K 和回答引用正确率。
7. 补齐容器、HTTPS、监控、备份和可重复发布脚本，再生成公开评审链接。

## 17. ASR API 云端识别补充

### 17.1 功能定位

本轮新增 `analysis_mode=api`，对应火山引擎豆包录音文件识别模型 2.0 标准版。它用于腾讯云小规格服务器上的高质量识别：不加载本地 `Whisper large-v3` 大模型，按音频时长调用云端 ASR，再复用现有 MiniMax-M3 摘要、章节和字幕校核流程。

本地精准模式仍保留给安装包版本。公网演示服务器点击“本地精准”时，前端会提示：服务器配置较小，暂不支持本地 large-v3，可体验快速识别或 ASR API 识别。

### 17.4 部署配置

公网 ASR API 模式需要在服务器环境变量中配置：

```env
XUNLEI_BACKEND_DOCKERFILE=Dockerfile.backend.cloud
XUNLEI_PUBLIC_BASE_URL=https://评委可访问的域名或公网IP
VOLC_ASR_API_KEY=
VOLC_ASR_APP_ID=
VOLC_ASR_ACCESS_TOKEN=
VOLC_ASR_RESOURCE_ID=volc.seedasr.auc
VOLC_ASR_BASE_URL=https://openspeech.bytedance.com/api/v3/auc/bigmodel
VOLC_ASR_POLL_INTERVAL_SECONDS=2
VOLC_ASR_TIMEOUT_SECONDS=600
```

新版火山控制台优先使用 `VOLC_ASR_API_KEY`；旧版控制台使用 `VOLC_ASR_APP_ID` + `VOLC_ASR_ACCESS_TOKEN`。真实密钥只允许放在服务器 `.env` 或 `backend/.env.local`，禁止提交到 Git。

腾讯云小规格部署使用 `Dockerfile.backend.cloud`，避免在公网服务器中安装 `torch`、`FunASR`、
`faster-whisper` 和 `stable-ts` 等大模型依赖。该模式下公网 Demo 主推 ASR API 识别，本地
Whisper large-v3 精准模式只在安装包或高配私有部署中开放。云端镜像直接使用基础镜像内置 pip
安装固定依赖，减少服务器额外下载 pip 或系统包导致的构建等待。

### 17.5 商业化表达

产品里将“高质量识别额度”作为会员/按量价值锚点：普通用户可使用快速整理，高价值用户或评委演示可使用 ASR API 获得更稳的中文识别；后续可把云端识别分钟数、任务优先级、批量整理和跨端同步设计为会员权益或按量包。
