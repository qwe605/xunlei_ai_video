# 迅雷 AI 片库：详细实施计划

> 版本：1.0  
> 日期：2026-07-28  
> 性质：项目内部执行计划，不作为评委阅读的最终产品方案  
> 目标交付：可公开访问的交互 Demo、真实离线处理样例、产品方案 PDF、3 分钟录屏和统一提交包

## 1. 执行原则

1. 先完成无需 GPU、API Key 和后端服务即可运行的评审 Demo。
2. 再接入一个真实视频处理样例，证明转写、分段和检索链路可执行。
3. 所有 AI 结果必须带证据和时间戳；没有证据时明确返回未找到。
4. 传统文件名搜索始终可用，AI 搜索只做增量增强。
5. Demo 数据可以预生成，但界面必须明确区分样例状态与真实处理状态。
6. GPL/AGPL 项目只参考架构，不复制源码、样式或品牌资产。
7. 每个里程碑完成后立即执行对应测试，不把验证集中到最后一天。

## 2. 最终范围

### 2.1 必须完成的提交主线

- 片库首页：展示 8 至 12 个命名混乱的视频与索引状态。
- 双模式搜索：传统关键词搜索和“问片库”自然语言搜索。
- 搜索结果：显示匹配原因、命中字段、相关章节、置信度和播放入口。
- 视频详情：摘要、标签、媒体信息、观看进度和智能章节。
- 播放器：章节侧栏、问视频、引用片段和时间点跳转。
- 状态覆盖：加载、空片库、无结果、低置信度、索引中、索引失败、无证据回答。
- 响应式：桌面 1440px、平板 768px、手机 390px。
- 可公开访问的静态部署。

### 2.2 必须完成的技术证明

- 一个自有或许可证清晰的短视频。
- faster-whisper 生成带时间戳字幕。
- PySceneDetect 生成镜头变化候选。
- 基于字幕语义变化生成章节候选。
- BGE-M3 或轻量兼容模型生成检索向量。
- 至少 10 条测试查询及 Recall@3、MRR 评估。
- 真实处理结果导出到 Demo，至少一个视频不是手写假数据。

### 2.3 本轮明确不做

- 迅雷真实账号登录和云盘 API 接入。
- 整个 20T 片库的在线处理。
- 在线运行 Qwen3-VL、NVIDIA VSS 或商业视频理解 API。
- 自动移动、删除或重命名用户文件。
- 生产级多租户、计费和会员系统。
- TV、Android、iOS 原生客户端。

## 3. 技术决策

### 3.1 提交 Demo

| 层级 | 选择 | 原因 |
|---|---|---|
| 前端 | React 19 + TypeScript + Vite | 开发快、静态部署稳定、适合交互原型 |
| 路由 | React Router | 支持片库、搜索、详情和播放器深链接 |
| 播放器 | Plyr | MIT、可访问、支持字幕和时间跳转 |
| 图标 | Lucide React | 避免手绘基础 SVG |
| 数据校验 | Zod | 在数据进入 UI 前校验预生成 JSON |
| 状态 | React 本地状态 + Context | Demo 状态规模不需要 Redux |
| 单元测试 | Vitest + Testing Library | 验证排序、时间跳转和组件状态 |
| 端到端 | Playwright + axe | 验证闭环、响应式、控制台和可访问性 |

### 3.2 技术样例

| 层级 | 选择 | 参考项目 |
|---|---|---|
| 媒体探测 | FFprobe | FFmpeg |
| 音频转写 | faster-whisper | SYSTRAN/faster-whisper |
| 精确对齐 | WhisperX，可选 | m-bain/whisperX |
| 镜头候选 | PySceneDetect | Breakthrough/PySceneDetect |
| 中文检索 | BGE-M3 | FlagOpen/FlagEmbedding |
| 混合检索 | BM25 + Dense + RRF | YT-Navigator |
| 重排 | BGE Reranker，可选 | FlagEmbedding、YT-Navigator |
| 生产存储 | PostgreSQL + pgvector，仅写架构与 API | pgvector |

### 3.3 开源复用边界

- 直接依赖：Plyr、faster-whisper、PySceneDetect、FlagEmbedding。
- 参考并重新实现：YT-Navigator 的 `Video`、`VideoChunk`、BM25/向量并行召回、重排和无证据拦截。
- 仅参考架构：Immich、Jellyfin、MoviePilot、NVIDIA VSS、Qwen3-VL。
- 不复制 YT-Navigator 中字符串拼接 SQL；所有查询使用参数化输入。
- 不把镜头切换直接当章节；镜头候选必须与字幕语义边界合并。

## 5. 核心数据契约

### 5.1 `Video`

必须包含：

- `id`：稳定字符串 ID。
- `title`：AI 或用户确认后的展示名。
- `originalFilename`：原文件名。
- `mediaType`：`tutorial | movie | series | meeting | game`。
- `durationSeconds`、`resolution`、`codec`、`language`。
- `posterUrl`、`videoUrl`。
- `watchProgressSeconds`、`savedAt`。
- `indexStatus`：`pending | processing | ready | failed | disabled`。
- `indexLevel`：`L0 | L1 | L2 | L3`。
- `confidence`、`summaryMode`、`spoilerProtected`。
- `summary`、`shortDescription`、`tags`、`chapters`。

### 5.2 `Chapter`

必须包含：

- `id`、`videoId`、`title`。
- `startSeconds`、`endSeconds`。
- `thumbnailUrl`、`summary`。
- `source`：`subtitle | scene | multimodal | manual`。
- `confidence`、`spoilerLevel`。

约束：

- `0 <= startSeconds < endSeconds <= durationSeconds`。
- 同一视频的章节按开始时间升序。
- 教程章节标题可直接展示；影视章节标题受防剧透状态控制。

### 5.3 `EvidenceSegment`

必须包含：

- `videoId`、`chapterId`。
- `startSeconds`、`endSeconds`。
- `text`：字幕或结构化证据。
- `sourceType`：`filename | metadata | subtitle | summary | visual`。
- `keywordScore`、`vectorScore`、`rerankScore`、`confidence`。

### 5.4 `SearchResult`

必须包含：

- `video`。
- `matchReasons`：面向用户的匹配原因数组。
- `evidence`：最多 3 个命中片段。
- `score`、`confidenceLabel`。
- `searchMode`：`exact | semantic | hybrid`。

### 5.5 `VideoAnswer`

必须包含：

- `answer`：不超过 120 个汉字的简短回答。
- `grounded`：是否有视频内证据。
- `citations`：0 至 3 个 `EvidenceSegment`。
- `confidence`。
- `fallbackReason`：无依据时的原因。

硬约束：

- `grounded=false` 时 `citations=[]`。
- `grounded=true` 时至少有一条 citation。
- UI 只能从 citation 生成跳转按钮，不能从回答文本猜时间。

## 6. API 契约

Demo 首先使用静态数据适配器，FastAPI 后端遵循同一接口。

| 方法 | 路径 | 用途 |
|---|---|---|
| `GET` | `/api/v1/videos` | 获取片库，支持状态、类型、排序筛选 |
| `GET` | `/api/v1/videos/{video_id}` | 获取摘要、章节与媒体信息 |
| `POST` | `/api/v1/search` | 传统、语义或混合搜索 |
| `POST` | `/api/v1/videos/{video_id}/questions` | 基于当前视频证据问答 |
| `POST` | `/api/v1/feedback` | 不相关、章节错误、信息纠错 |
| `GET` | `/api/v1/health` | 本地技术样例健康检查 |

统一错误格式：

```json
{
  "error": {
    "code": "NO_EVIDENCE",
    "message": "当前视频中没有找到相关内容",
    "requestId": "req_demo_001",
    "details": {}
  }
}
```
