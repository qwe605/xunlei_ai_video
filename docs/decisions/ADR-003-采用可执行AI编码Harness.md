# ADR-003：采用可执行 AI 编码 Harness

## 状态

已接受

## 背景

项目已有产品规范、Skills、schema、单元测试和 E2E，但完成流程依赖代理逐条记忆命令。
缺少统一验证入口、运行凭证、训练/留出评测与晋级规则时，无法判断一次提示词或 Skill
调整是否真的提高了跨任务成功率。

## 决策

采用项目内可执行 Harness：

- `tools/verify.ps1` 是开发完成的统一验证入口，并始终生成 JSON 运行凭证。
- `harness/evals/train.json` 用于工作流迭代，`holdout.json` 由独立评测者用于晋级。
- 评测资产使用 JSON，而不是引入 YAML 解析依赖；PowerShell 可以原生解析并校验 JSON。
- 产品测试和 AI 编码评测分别计分，不能互相替代。
- 候选 Harness 必须同时满足自动门禁、训练集不退化、留出集不退化和独立复核。
- Trace 只保存最小工程元数据，用户内容必须在进入失败样本库前脱敏。

## 后果

- 任意代理和 CI 可以通过同一命令获得一致的完成证据。
- 新增 Skill、提示词或工具说明需要通过评测证明价值，避免只凭主观感受扩充上下文。
- 首批任务型评测仍需独立 worktree 和人工判定，暂时不能完全自动化。
- 本地项目中的留出用例对评委可见；生产团队应将其迁移到实现代理无权限的评测仓库。
