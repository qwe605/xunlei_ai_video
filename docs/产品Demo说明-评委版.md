# 迅雷 AI 片库 Demo 说明

## 产品定位

迅雷 AI 片库面向拥有大量云端视频的用户，通过 AI 自动理解文件信息与视频内容，让用户
用一句自然语言找到目标视频，并通过摘要、智能章节和视频问答直接到达关键片段。

> 海量视频，一句话找到。

## 真实用户问题

当云盘积累到数 TB 甚至 20T 后，用户经常只记得演员、场景、知识点或保存时间，却记不住
准确片名。下载资源的原文件名又常包含发布组、编码和缩写，传统文件名搜索和影视刮削
无法稳定解决“我明明存过，但找不到”的问题。

即使找到了视频，用户仍要逐个试播、反复拖动进度条，才能确认其中是否包含目标内容。

## Demo 展示的产品闭环

1. **AI 整理片库**：片库展示 AI 已整理、正在生成摘要、等待分析、识别失败等状态，
   但不会修改用户原文件。
2. **一句话找视频**：输入“找讲 Cookie 登录的 Python 视频”，系统同时理解标题、
   原文件名、摘要、标签和章节。
3. **解释为什么匹配**：结果不只给出视频，还会说明命中的内容标签和相关章节。
4. **打开前先看懂**：详情页展示一句话简介、整片摘要、媒体信息和智能章节。
5. **章节直接跳转**：点击 `12:36 登录与 Cookie`，播放器从该时间点开始。
6. **问视频并跳转**：追问“后面有没有讲登录失效？”，回答引用 `18:45—20:05`
   的视频证据，并提供跳转按钮。
7. **没有依据就拒答**：询问视频中不存在的内容时，系统明确说明未找到，不使用模型
   常识生成看似正确的回答。

## 核心创新

本方案没有把 AI 做成播放器旁边的孤立聊天框，而是让同一套视频内容索引贯穿：

> AI 整理片库 → 一句话找视频 → 摘要与章节 → 问视频 → 跳转关键片段

AI 的价值因此不是“多一个回答入口”，而是减少翻目录、猜文件名、错误试播和拖进度条
这四类真实操作成本。

## Demo 数据说明

为了保证评审环境稳定，Demo 使用预生成的视频索引，不要求现场安装模型、下载权重或
配置 API Key。以下能力由 Demo 实际执行：

- 搜索模式切换与结果排序。
- 搜索匹配原因与置信度表达。
- 数据结构和时间范围校验。
- 视频问答的证据约束与无依据拒答。
- 本地视频在 `12:36`、`18:45` 等时间点的真实跳转。
- 桌面与移动端响应式交互。

演示图像和视频为产品展示生成的合成素材，不包含真实用户数据。生产化后，字幕、章节
和索引可由成熟开源组件在后台预计算，数据结构与当前 Demo 保持一致。

## 生产化技术路径

```text
云盘视频
  → FFprobe 读取媒体信息
  → 优先读取已有字幕
  → 无字幕时使用 faster-whisper 转写
  → PySceneDetect 提供镜头变化候选
  → BGE-M3 生成中文语义向量
  → PostgreSQL + pgvector 保存元数据与索引
  → BM25 + 向量召回 + 重排
  → 搜索结果、摘要、章节、回答证据和时间跳转
```

影视内容默认开启防剧透；用户视频、字幕和向量索引继承原文件访问权限，不用于公共推荐。

## 建议演示路径

1. 从片库首页点击推荐问题“找讲 Cookie 登录的 Python 视频”。
2. 查看第一条结果的“为什么匹配”和 `12:36` 相关片段。
3. 进入详情页，浏览摘要和 6 个智能章节。
4. 点击“登录与 Cookie”进入播放器。
5. 切换到“问视频”，选择“后面有没有讲登录失效？”。
6. 点击 `18:45—20:05` 的证据片段。
7. 再输入一个视频中不存在的问题，展示诚实拒答。
